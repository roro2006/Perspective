# T5-33 notes: live demo console

- **Built:** `curio_robot/demo/` (session engine, stdlib HTTP + server-sent events, status,
  one static page) and `docs/demo.md`. Start: `uv run python -m curio_robot.demo`.
- **Real pipeline:** the target is `pipeline.step` on fresh MuJoCo renders (detector, fusion,
  perspective, rule resolver). Curio on fuses the head camera, off is robot-only, as `sim.ab`.
- **Ground truth:** `oracle_xy` reads true positions and the person's true eye and gaze with
  the scenarios' rule. It agreed with `Scenario.expected_xy` on all 120 scenes checked (60
  seeds each of perspective and occlusion) and on 8 seeds of every kind in the tests.
- **Seed choice:** off is wrong and on is correct on 51 of 60 perspective seeds and 60 of 60
  occlusion seeds at 480x360. The showcase uses perspective 0 and occlusion 1. At 240x180,
  perspective 3 flips the other way, because one red block is too small for the robot's
  detector. So the resolution matters, and the demo and tests both use 480x360.
- **Decisions the spec left open:** no trained VLM grounder on this machine, so the console
  runs the geometry pipeline and says so in its preflight. The arm is scripted IK and is
  labelled that way. The drop-in panel reads card statuses from tasks/ at startup.
- **Worries:** the handoff's LIBERO live mode isn't here (T5-31 hasn't run). The rule
  resolver handles colour plus left/right/nearest/farthest only. Free wording outside that
  is answered by the rule and shown with truth "unknown".
