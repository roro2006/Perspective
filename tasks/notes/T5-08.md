# T5-08 notes

- `scripts/smolvla_eval.py`: loads a checkpoint with `smolvla_train.build_policy` (same config
  handling: load_vlm_weights=False, two cameras) and `make_pre_post_processors(pretrained_path)`
  with the device step overridden; rolls out in PhysWorld at the checkpoint's image size.
- Scenes: seeds 50000+ (demos 1000-1300), no box, target a random pair block, words from
  `demos.words_for`; seeds where a pair block is off the robot image are skipped. Conditions
  marker / words / swapped share scenes, targets and the torch noise seed.
- Timing: 10 Hz observations, each action covers 5 ticks of 20 ms; open decision: ctrl ramps
  linearly from the previous action inside the 0.1 s (the expert's ctrl was a smooth ramp and the
  recorded action is its value at the end), `--ctrl hold` for constant. Chunks via
  `select_action` with the checkpoint's n_action_steps (50); `--n-action-steps` overrides.
- Pick = lifted >= 3 cm continuously for 0.5 s, checked each 20 ms tick (the expert checks at
  two instants, so this is slightly stricter). Horizon 6 s.
- `--device cpu` sets CUDA/HIP_VISIBLE_DEVICES="" before torch is imported (torch imports are
  lazy for that reason). No DataLoader, so no hang at exit; both smoke runs exited with code 0.
- Smoke (CPU, smoke checkpoint, 2 scenes, marker, 3 s): 41 s per model call, 41 s per rollout,
  17 s load; outcomes nothing/nothing (the arm moves toward the table). A 1-scene swapped run
  with --n-action-steps 10 made 2 calls in 2 s, so chunk re-querying works. Output in
  out/smolvla/eval_smoke.
- Worry: with n_action_steps = chunk = 50 frames and 42-frame episodes, one call plans nearly the
  whole pick open loop, and frames past 42 were trained on padding. Worth also running
  `--n-action-steps 10` on the real checkpoint to see if closing the loop helps.
- Worry: CPU is far too slow for the real eval (~80 s per rollout); use the GPU after training.
