# T2-11 notes

- `RuntimeConfig.grounder` (default None). With it, Runtime makes a `FrameHistory`; `Runtime.tick`
  calls `PerceptionStage.remember(frames, t0)` so every human frame is kept with its capture
  time, including frames the perception slot drops. Without a grounder nothing is created or sent.
- Orchestrator takes `grounder=` and `history=`. On the final: anchor = `anchor_time(words)` or
  the final's `t` (speech end); frame = `history.at(anchor)` or `latest()`. Marks, render,
  `build_request` and `score` run on the pool; a `GroundingReply` is always posted, with source
  "error: ..." if rendering fails. If there's no frame, the old path runs (text VLM or confirm).
- With a grounder configured the text VLM isn't asked as well, so only one source can redirect.
- Open point: "that one" doesn't give *no* readings. `enumerate_readings` returns every object
  uniformly, so decide says "ask". I ground hedge/ask decisions too, and empty readings when the
  request has no colour. If fusion can act, the arm goes there; if not, the old question is asked
  (and `_asked` is set, so "yours"/"mine" still works). An absent colour still gets "I don't see a
  green one" and never goes to the grounder.
- Redirects need the fused top to differ from `last_target` and clear the act threshold. They use
  tag "vlm" and update `_committed.chosen_id`. The reply is recorded as stage "vlm" with the fused
  posterior. Stale replies (wrong utterance, or interrupted) are dropped. `done` waits for them.
- STT: `transcribe_words` is an optional method (verbose_json dict), so `Transcriber` is
  unchanged. The final uses it when present, with offset = time of the buffer's first block
  (pre-roll included). `WhisperCppServer.transcribe_words` field names are a guess until T2-10.
- `run_live(..., grounder_url=)` added. The CLI (`sim/cli.py`, not owned) has no flag for it yet.
