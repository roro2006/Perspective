# T5-06 notes: grounding LoRA v2 on benchmark-style data

- New `scripts/bench_lora_data.py`: for seeds 11-19 it draws `bench.items.make_item`
  kind-major from one rng per seed (the same stream as `generate`, but with counts per
  kind) and writes the `conditions.build("geometry", item)` request as grounding_data
  rows, using the PNG bytes from the data URL. `train_lora.py` reads them unchanged, so
  it was not edited. Seed 0 and 70000+ are refused. Test: `tests/test_t5_lora_data.py`.
- Mix (my call): free 112, hidden-pair 90, marked 56, habit 56, colour 34, hidden 34
  per seed, plus 600 target-2 deictic rows (`--deictic-from`) so "that one" is not
  dropped. 4,038 rows in total, 3,589 train and 449 held out by id hash. A check
  found no image shared with bench5b.
- Trained from the base model with the r16 defaults: 675 steps, 56 minutes, held-out
  accuracy 0.80, 0.87, 0.89. Adapter at `out/lora/qwen3vl4b-r16-v2`, served as
  `llama/models/lora/curio-ground-r16-v2-f16.gguf`. The old adapter is untouched.
- bench5b geometry, old -> new: free 0.64->0.90, marked 0.94->1.00, habit 0.70->0.72,
  hidden-pair 0.92->1.00, colour and hidden 1.00. **Gate PASS.** p50 110 vs 110 ms on
  the same 449 requests, each on a fresh server.
- E2E lora2 (run1): ring 0.945, target 0.14, partner 0.01, nothing 0.85 (oracle: 0.14,
  0.00). Before the run I backed up out/e2e/run1/summary.json as
  summary_before_t5-06.json, because `rollout --setups lora2` overwrites it with
  lora2 only. The summary was rebuilt afterwards with all five setups; the finished
  rollouts were skipped.
- Worry 1: deictic regressed on the target-2 held-out set (served: 0.55 -> 0.45). It is
  not gated, but the live pipeline uses it. More deictic rows would fix it.
- Worry 2: training and test free wording share FREE_TEMPLATES, so 0.90 shows
  generalization to new scenes only. A held-out-template check would be the honest
  next test.
- The robot-only and paired scores shifted (robot-only free 0.52 -> 0.30). They are
  reported, not gated.
