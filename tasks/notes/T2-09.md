# T2-09 notes: LoRA training script
- `scripts/train_lora.py`: `--dry-run` loads the JSONL, fails clearly on missing images or a stale `prompt_version`, prints counts by kind, answer letters and the train/eval split; torch/transformers/peft are imported only inside `train()` (a test checks they stay out of `sys.modules`).
- Training: `AutoProcessor` + `AutoModelForImageTextToText` (Qwen2.5-VL / Qwen3-VL). The prompt is the user turn through the chat template with `add_generation_prompt=True` (what vLLM serves); the answer letter is appended as one token and is the only labelled token (`answer_labels` raises if a letter is not one token, which checks the design doc's [VERIFY]). Eval: answer-token loss and accuracy of the argmax over the example's own letters, per epoch, into `train_log.jsonl`.
- Defaults for 20 GB: bf16, gradient checkpointing (non-reentrant), batch 1, grad accum 16, AdamW lr 2e-4, 3 epochs, linear warmup 5%, LoRA r=16 / alpha 32 / dropout 0.05 on q/k/v/o_proj (vision tower uses qkv/proj, so it stays frozen).
- Hold-out: sha256(id) bucket < 10% -> `eval_ids.json`; stable across dataset sizes, but a tiny set can have 0 eval rows (warning). `train_config.json` has model, data path + sha256, PROMPT_VERSION, counts, hyperparameters.
- pyproject: new extra `train` (torch>=2.5, transformers>=4.57, peft>=0.13, accelerate>=1.0); `uv lock` re-run so uv.lock matches (uv.lock is outside `owns`; the one allowed exception). Nothing was installed.
