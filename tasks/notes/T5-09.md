# T5-09 notes

- `scripts/e2e_eval.py ground|rollout`. Trials: kinds my/your/habit/color in turn, seeds 70000+,
  each trial takes the next usable seed. Pair kinds keep only scenes where the person's and the
  robot's side disagree (as bench items), so a frame-blind grounder is right half the time;
  scenes with target or partner outside the 256x256 policy image are skipped.
- The grounder request is `bench.conditions.build("geometry", item)` on a `BenchItem` built in
  the script from a PhysWorld(320, 240) render (benchmark size); no bench/ changes. Object
  positions are `true_map` (as the benchmark), pixels use the settled block centres.
- Rollout reuse without editing smolvla_eval: its "marker" condition rings `Trial.target`, so
  the chosen block is passed as `Trial.target` and the outcome is rescored against the true
  target here. Side effect: `ring_block_max_lift_m` is the ringed block's lift, not the target's.
  A grounder with no answer (error) gets no ring, like words-only, and counts as wrong.
- `ground` stops without writing if every request fails (server down); a second grounder run
  must reproduce trials.jsonl exactly or it stops. `rollout` appends rollouts.jsonl and skips
  finished (setup, id) pairs, so an interrupted GPU run resumes.
- Smoke (CPU): fake ground, 8 trials, 1.3 s. Rollout with the 100-step smoke checkpoint, 1
  trial x words/base/oracle, 1 s horizon: 41-45 s per model call, all "nothing"; rings at the
  chosen block's policy pixel; rerun skipped all three. Output out/e2e/smoke.
- Worries: (1) the policy was trained only on "on my left/right" and colour words, so "your"
  and "the left" are unseen phrasings in every setup; words-only on those kinds is expected to
  be poor, and ringed setups test whether the ring overrides odd words. (2) habit: the policy
  never sees the habit, only the grounder does. (3) 800 rollouts at ~1-2 s each on GPU is fine;
  the policy is reloaded even when a rerun has nothing left to do (~20 s).
