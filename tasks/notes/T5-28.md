# T5-28 notes: Curio drives pi0

- **Credit**: pi0 is Physical Intelligence's model (openpi), run as `lerobot/pi0_base` through
  LeRobot 0.6. Its PaliGemma backbone is under the Gemma terms of use, which the user accepted.
- **Data**: out/demos800b (800 episodes, 35,996 frames; 32,417 train frames from episodes 0-719,
  3,579 held out from 720-799). Relabelled with robot-words text built from each true target
  (20 distinct tasks). Cameras: robot -> base_0_rgb, wrist -> left_wrist_0_rgb. **Ring**: the
  stored PNGs never had it (smolvla_dataset draws it when a sample loads). Check: 0 ring
  pixels in 612 sampled frames. pi0 never sees a ring or the head camera.
- **Training**: one run, train_expert_only (578M trainable), bf16 VLM with fp32 expert weights,
  batch 16, 22,000 steps in 406.6 min, peak 15.6 GB allocated. Train loss ended near 0.001.
  Held-out loss was 1.18 at step 2k, 0.71 at 4k, then 0.96-1.43 until 22k (0.968 final).
- **Restart**: the first agent died from a network error after training. A second agent ran
  the gate once (checkpoint 022000, no retraining). The goals for 51000-51099 had been resolved
  before training, and the code reuses them. The grounder ran beside pi0 (9.1 GB peak, fits).
- **Gate: FAIL on line 3.** pi0 lifted no block in any of the 300 rollouts (A = B = O = 0.00,
  Wilson [0, 0.037]). Line 1 fails, and line 2 "passes" only because 0 >= 0. SmolVLA run 5 on the
  same seeds: A 0.05, B 0.51, O 0.59. Curio picked the true target on 99 of 100 scenes.
- **Worry (diagnosis after the gate, not a rerun)**: the loaded checkpoint predicts near-zero
  joint targets even on training frames (normalized joint 4 is about -7), so the arm falls
  toward the zero pose. Weights load exactly as stored (the expert loses only bf16 rounding;
  keeping it fp32 changes nothing). Saved normalizer stats match the data. But the training-path
  loss on a training frame is 3.76, against about 0.002 logged in training. So the policy being
  evaluated doesn't behave like the one that was trained. The likely cause is a train/inference
  mismatch in the pi0 harness, and the root cause is not found. I left it there: the GPU passed
  to T5-29. Anyone rerunning should first reproduce the logged eval_loss from the checkpoint.
