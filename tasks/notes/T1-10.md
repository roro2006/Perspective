# T1-10 notes

- `sim/live.py`: `ReactiveVoice`, a VoiceIn that says the request (same pacing/partials as
  ScriptedVoice), then polls a `react()` callback for its next line; `idle_for()` tells the runner
  when the person has gone quiet.
- `sim/learn.py`: `live_learning(user, requests, seed)` runs one Runtime per request (fresh tracker
  and waterfall) on a new `scenarios.perspective` scene in the same SimWorld; the belief carries over
  through the person's ProfileStore (a temp dir unless `profiles_dir` is given).
  `_Reactor` decides what the person says: "yours"/"mine" when a robot line contains "or mine?",
  else "no, the other one" if `brain.last_target` is not the intended block, judged 0.3 s after
  the request's final (so it lands mid-motion or right after arrival, inside the learning window).
  Ground truth is `SimUser.intended` on the live map, so ids match the orchestrator's.
- No VLM in live learning: MockVlm is the rule resolver (always speaker frame) and would redirect the
  arm against what was learned. Feeding the VLM into the posterior is target 2.
- CLI: `curio-sim learn --live` (`--users/--noise/--baseline` ignored). `--seed` now defaults to None:
  0 for fast mode (unchanged), 1 for live, because seed 0's robot-frame person (p_own 0.05) happens
  to answer "mine" at request 4, which muddies the stage demo. Honest, but worth knowing.
- Demo: 6 requests in ~43 s; smoke test (3 requests, seed 1) ~21 s. Outcomes are timing-based but
  have >1 s of slack (react 0.3 s after final vs. ~1 s+ arm travel and a 2 s accept window).
- Only the request utterance's waterfall is printed; answer/correction utterances aren't.
